# Bundled resource inventory

The repository-level Apache-2.0 license applies only to material for which the
BaoIAD contributors can grant those rights. It does not relicense third-party
datasets, derived images, trademarks, fonts, icons, or other embedded content.

The machine-readable authorization record is
[`asset_approvals.json`](asset_approvals.json). Every current asset is bound to
an exact SHA-256 and remains a public-release blocker until the technical,
brand, and legal-or-OSS roles approve each intended surface. If approval is not
recorded, the asset must be omitted or replaced before release.

No signatures, private email addresses, credentials, or underlying legal
documents belong in this public inventory. Approved records should use an
opaque internal evidence reference.

## Approval scopes

Approval is surface-specific. The record distinguishes GitHub repository,
Read the Docs, GitHub social preview, WAIC event use, and press/marketing use.
Approval for one surface does not imply approval for another.

The two MVTec-derived images are deliberately fixed to
`github_social_preview: false`. Removing an image from a README is not enough
if the binary still remains in the public release tree.

## Reproduction limits

- The hero, logo, and architecture diagrams have no tracked editable source or
  generator, so the current PNG/SVG files are the only repository evidence.
- `scripts/gen_vis_multi_model.py` imports an untracked SPADE implementation
  and depends on external datasets, checkpoints, and an unrecorded environment.
  Its output is a qualitative illustration, not a performance result table.
- `scripts/gen_vis_examples.py` uses unseeded randomness for the displayed
  synthetic anomaly map.

These limits must remain visible unless a new, authorized source package and a
verified reproduction procedure replace the current evidence.
